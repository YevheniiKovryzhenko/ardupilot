# Node 70/71 — G474 avionics and spray actuators

## Build

This is an **alternative image for one physical G474**, combining the two roles under numeric **CAN node ID 70**. Standalone node-70 and node-71 targets remain available.

```sh
./waf configure --board Aircraft-G474-70-71
./waf AP_Periph
```

Upload `build/Aircraft-G474-70-71/bin/AP_Periph.bin` through the existing MatekG474-Periph bootloader. Do not upload the extensionless ELF file. Hardware board ID remains **1170**; isolate the intended board during board-ID-based firmware updates to avoid replacing other G474 role images.

Local build passed with ARM GCC 13.2.1: **218,689 bytes flash used, 268,672 bytes free**. Hardware operation remains untested.

## Included functions

- SF45/B on UART1, including the paired raw-sample CAN extension.
- US-D1 on UART4.
- Here4 on CAN2 with bidirectional CAN1/CAN2 forwarding.
- MS4525 airspeed support, as in node 70.
- Pump and two nozzle ESC outputs on pads 1–3, sharing TIM2, conventional 1000–2000 µs PWM at 50 Hz.
- Two independent valve-enable GPIOs on pads 5–6, using hardpoint IDs 0/1.

No pin conflict exists between those sensor interfaces and actuator outputs. Pads 5/6 are explicitly removed from PWM and configured as GPIO LOW at initialization. Other inherited PWM outputs are unassigned. Combining the roles couples avionics and spray control to the same MCU, power supply, reboot, and firmware update; validate simultaneous sensor and actuator operation under load before choosing this layout for installation.

## Minimal setup for bench testing

1. Choose this combined image **instead of** the separate 70 + 71 arrangement. Do not also power another node with ID 70. A separate node 71 using the same actuator/hardpoint IDs would respond to the same broadcast commands; disconnect it or deliberately remap commands.
2. Wire sensors as on node 70 and spray actuators as on node 71, using the table below. Keep the two CAN segments separately terminated. Sensor and actuator power remain separately provided as previously planned.
3. On a fresh configuration, the defaults below are embedded. Updating an existing node does **not** necessarily replace saved parameters: read them back and apply the combined `defaults.parm` values explicitly, or deliberately reset the node and restore needed settings. The inherited parameter format is still version 4; no additional automatic erase is introduced.
4. PX4 SF45 settings remain source node 70 / sensor 0. Keep the existing sensor receiver settings. PWM commands use wire actuator IDs 5/6/7; valve commands use hardpoint IDs 0/1. These identifiers are independent of CAN node ID.
5. Complete the [node-71 command integration and commissioning checks](node-71.md#command-integration-and-commissioning). PX4 automatic spray control is not implemented by this alternative image. GPIO-to-BEC EN compatibility and reset/unpowered behavior remain unverified. Valve outputs latch the latest command and have no CAN-loss timeout; motor timeout stops pulses, which still requires ESC stop-response testing.

Node 80 is still needed for the proposed pressure/flow/current analog sensing arrangement. Its acquisition and telemetry work remains pending; this combined image does not implement those sensors.
